# 05 图片/视频变更渲染

Karpathy 原则的落点：agent 输出从聊天文本升级为**可渲染制品**——
人 glance 即懂。铁律先行，再分三层。

## 铁律

1. **图的 source of truth 是代码**：mermaid/drawio/diagram-design 源文件进 git；
   HTML/PNG/MP4 是 CI 确定性渲染的 build artifact，**绝不手改产物**。
2. 渲染物是 reviewer 的**辅助证据**，结构化 verdict 才是门禁本体；
   禁止"图好看就放行"。
3. 一切渲染先过金标：5 个历史 PR 渲图/视频，人工判"看渲染物 vs 读 diff
   哪个抓重点快"，过线才进模板。

## 三层嵌入

### L1 PR 附图（P4，立即可做）

- 工具：diagram-design（Agent Skills 标准；先作工作站 omp skill 手动用，
  稳定后封 Actions step）。
- 触发：PR 涉及架构/网络/存储变更时，executor 在任务卡里声明需附图。
- 链路：源文件进 PR → **GHA step** 渲染 HTML→PNG（ubuntu-latest + headless Chrome）→
  **GitHub 无 PR 附件官方 API** → PNG 传 versitygw S3 桶（内网，手机经 tailnet 打开）
  或 GitHub Release 附件（公开）——拍板项；sticky comment 嵌链接 →
  飞书卡片直接带图（手机端可读性：markdown 表格在手机上不可用，图是解药）。
- PNG 量级小（<500KB），S3 桶或 Release 附件皆可承载，无额外存储设计。

### L2 PR 讲解视频（P4，HyperFrames）

- 工具：heygen-com/hyperframes（Apache-2.0）——agent 写 HTML+时序属性，
  headless Chrome+FFmpeg **确定性渲染** MP4；本地 CLI，无云依赖；
  现成技能 `/pr-to-video`（PR→带动态 diff 的变更讲解视频）。
- 形态：**GHA step**（ubuntu-latest + apt ffmpeg，或 Node22+FFmpeg 容器镜像），merge 事件触发，
  30s 级别。渲染确定性 → 可进 CI 回归（同输入同输出）。
- 旁白：VoxCPM2 TTS 车道（audio lane 现成，零新增部署）。
- **存储边界**：MP4 不进 git。传 GitHub Release 附件（公开）或 versitygw S3 桶（内网）——与 L1 同一拍板项；
  飞书卡片只发链接+缩略图。

### L3 视觉 diff / Diagram-as-Test（P4 后置，等 infra PR 真实流量）

- drawio-skill 的 prdiff：CI 渲染 PR 结构 diff（增绿删红）——K8s manifest /
  Terraform 类 PR，"图变了哪里"比 yaml diff 可读性强一个量级。
- Diagram-as-Test：架构规则写成 YAML/JSON（如"internet 不得直连数据库"）
  在 PR 上强制——与 kubeconform 正交（一个查 schema，一个查拓扑）。
  先 shadow 只报不拦，误报 <10% 再挂门禁。
- 数字孪生场景：从 live `kubectl get -o json` 生成架构图，executor 的 infra
  修复 PR 需过拓扑规则——reviewer 从"看 diff"升级为"看图谱"。

## 与 reviewer 的关系

渲染产物进 reviewer 的 evidence（omni 车道有视觉能力，可审图）：
附图/视频链接写进 PR sticky comment 的固定段，reviewer 证据收集器一并读取。
注意 promptGuard：渲染 HTML 含仓库内容，走 guarded 车道即可；
误杀则该步换 `complex-raw`。
