# 06 新应用 / 新 agent 工作流接入协议

目标：整套架构的终态不是"一堆 agent"，而是**一套审计链上长出来的多个工种**。
任何新组件进 lab，过三道闸。

## 闸一：准入双过滤器 + 末日手搓

1. **越用越聪明 × 现有算力可及**：不积累数据/不沉淀规则的组件不接；
   算力够不着的 lane 不硬上。
2. **末日手搓**：断供（无公网、无厂商云）下是否刚需？非刚需排后。
3. 信任边界：数据出域一律默认拒绝；例外（如 Dropbox 同步）显式记录。

## 闸二：GitOps 接入模板（长驻 app）

新 app 一律走现有模式，禁止新约定：

```
kubernetes/apps/<namespace>/<app>/
├── ks.yaml                 # Flux Kustomization, config.home-ops.io/managed
└── app/
    ├── helmrelease.yaml    # app-template 优先; hostUsers: false (ADR-03)
    ├── externalsecret.yaml # 1Password ClusterSecretStore, 无明文
    ├── ciliumnetworkpolicy.yaml  # egress 收敛: LLM 只走 agentgateway,
    │                             #   MCP 只走 /mcp/{ro,rw,ext} guarded tier
    └── httproute.yaml      # kgateway-internal + authentik forward-auth
```

- SSO：`components/authentik`；备份：`components/kopiur/backup`。
- 沙箱：`hostUsers: false` + CNP 是边界（Kata 已死，见 ADR-03）。
- 资源限额必填；Kata/特权模式一律拒。

## 闸三：验证协议（agent 工作流 / 自动化）

每个新 agent 工种（reviewer 之外的 executor 场景、自愈、家务自动化…）：

1. **金标集**：历史实例 + 人工判定，盲审一致率 ≥90%。
2. **Shadow 期 ≥2 周**：只报不做/只评论不门禁，盯误杀率（>10% 回炉）与漏杀。
3. 过线才进自动档；门禁类一律 fail-closed 且有记录的人工绕过流程。
4. 事件模型对号入座：repo 事件 → **GitHub Actions（原生）**；监控/告警 → hermes webhook
   route；定时 → GHA schedule / hermes cron / K8s CronJob；**不给 Woodpecker 加 agent
   职责，Forgejo Actions runner 不复活**。

## 新 LLM 消费方纪律（已有架构的硬约束）

- LLM 只走 agentgateway 车道（complex/complex-raw/omni/micro），**禁直连 studio**；
  车道选择按 `ai.md` lane-fit：分类/路由=micro，保真敏感=omni，agentic=complex。
- MCP 无 open lane：只走 `/mcp/ro|rw|ext`（mcp-guardrails FailClosed）。
- 新增 OTEL 消费方接 Langfuse（5% 采样注意：决策类 span 用 always_on，
  照 reflex 模式）。
- embeddings/rerank 走 media 车道（qwen3-embedding-0.6b / reranker-0.6b），
  不自建。
- **CI 消费方凭证分离**：CI 侧（reviewer/executor/挖掘管道）走 environment `ci-llm`
  + CI 专用 key + `tag:gha-ci` ACL；与交互消费方（hermes 等）凭证分离，独立吊销。
