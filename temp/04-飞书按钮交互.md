# 04 飞书按钮交互（审批卡片 + 回调 + 叫停）

## 现状资产

- hermes-agent 飞书插件：**websocket 模式**（`FEISHU_CONNECTION_MODE=websocket`）、
  `FEISHU_ALLOW_BOTS=mentions`、群聊 allowlist、home channel、
  `FEISHU_ALLOWED_USERS` 操作者白名单。凭证在 1Password `feishu` item
  （app_id/app_secret/encrypt_key/verification_token 全齐）。
- trendradar 用 custom robot webhook——只能发不能收，不适用按钮。
- 回调写回 GitHub 的模式现成：mcp-github（ToolHive internal-rw，已部署）或
  任务侧 `GITHUB_TOKEN` 直连 API。

## 关键机制选择：websocket 收 card action

飞书互动卡片按钮回调有两条路：

| 路径 | 要求 | 适配 |
|---|---|---|
| **websocket 长连接收 card action 事件** | 无需公网/内网回调地址 | ✅ 首选——websocket 模式的红利，零新增 ingress |
| webhook 回调地址 | 需可达 endpoint + 验签 | 备选（薄 receiver，见下） |

**P3 前置验证**：hermes 飞书插件是否支持 interactive card 发送 +
card action 事件处理（读插件 `plugins/platforms/feishu` 源码/文档）。
若不支持 → fallback：servitor-apps 起一个 ~200 行薄 receiver（fastapi 级），
接飞书回调 → 验签（encrypt_key/verification_token）→ 转发 hermes webhook route
（`/p/ops/webhooks/<route>`，HMAC，frigate-alert 同款）。receiver 保持薄壳——
复杂度全留 hermes/GitHub 侧，换通知载体时一小时重写。

## 卡片规范

固定字段，防误触优先于美观：

```
标题: 【决策请示】<任务卡标题>            ← 或【审查告警】/【停滞告警】
正文: 决策点一句话 · 置信度 · PR 链接(GitHub) · 影响面一句话
按钮: [选A] [选B] [驳回] [转人工]         ← value 带结构化 payload
      {"decision_id":"…","choice":"A"}   ← decision_id 关联 Langfuse span/任务卡
```

- **叫停键**：独立高优卡片或指令词，effect=cancel 运行中 agent-job
  （GHA run cancel API）+ 飞书确认回执。
- 每日摘要：home channel，cron 产出（已有 ops profile 模式）。

## 审计闭环（铁律）

按钮回调结果必须写回 git：

```
卡片按钮 → ws/receiver → hermes ops → ① 执行动作(dispatch/cancel/评论)
                                    ② GitHub PR 评论:
                                       "决策: 选A · 置信0.93 · <操作者> · <时间>"
                                    ③ Langfuse span(decision_id 关联)
```

手机上的每次拍板因此进入 git 永久历史，与 reviewer verdict 同链。

## 安全

- 卡片按钮校验操作者 open_id ∈ `FEISHU_ALLOWED_USERS`（已有字段）。
- receiver 路径强制验签；hermes 侧 CNP 已收敛 egress
  （agentgateway + kube-dns + open.feishu.cn，无直通 GitHub——
  写评论走 mcp-github 的 guarded `/mcp/rw` 或显式加 CNP 条目，二选一在 P3 定）。
